# Reproduction

## 1. Check the published results without a GPU

Python 3.11 was used for the data-only checks. The exact observed NumPy, SciPy,
Matplotlib and PyYAML versions are pinned in `requirements-analysis.txt`.

From this repository's root, in a Python environment:

```bash
python -m pip install -r requirements-analysis.txt
python scripts/check_results.py
python scripts/plot_results.py
```

The checker independently reconciles copied-file hashes, all 144 native execution
CSVs against the consolidated 11,109 action records, success thresholds and first-hit
stopping, the Wall native route endpoints and within-pool regret, and the Reach-Wall
published per-pool arithmetic. It also checks local documentation links and Python
syntax. The large unpublished candidate databases are not inferred from aggregates.

Figure generation writes **`figures/reproduced/`** by default, leaving the reviewed
exports used in the README intact. The generated manifest lists input hashes.
No simulator, encoder or world model runs. Reach-Wall all-episode curves reuse the
study's plotting function and exact unsmoothed measurements. The lightweight Wall
route renderer uses the published trajectory cache and geometry; visual styling can
differ from the original native-wrapper export, but routes and selected identities
are the same. The paired-episode reproduction starts at action 1 because native
action-zero distance was not logged.

The README's added Wall regret figure can be generated by itself:

```bash
python scripts/plot_results.py --only wall-regret --output-dir figures
```

### Recompute the complete Wall ranking analysis

All Wall candidate-level scores are published, so its terminal control can be
recomputed directly, rather than only checking aggregate tables:

```bash
cd jepa-wms
python -m evals.simu_env_planning.planning.analyze_wall_terminal --input ../data/wall/scored_candidates.csv --output-dir ../runs/wall_terminal_recomputed
```

The original ranking and terminal-criterion tests run without simulation:

```bash
python -m unittest tests.test_candidate_analysis tests.test_wall_terminal tests.test_reach_wall_c tests.test_reach_wall_terminal -v
```

The repository's analysis CI runs this test selection and the public-data checker.

## 2. Rerun native planning experiments

The released data-only package does not include checkpoints, trajectory datasets,
MuJoCo snapshots or candidate `.pt` bundles. Fresh simulator experiments require
those assets and additional dependencies. In particular, the published Reach-Wall
tables do not contain all 1,517,040 raw candidate scores. To rebuild those scores,
first rerun A to generate its simulator snapshots and captured actions.

### Environment and assets

The original study ran on Windows with an existing conda environment named `AI`,
Python 3.11, PyTorch 2.5.1, Meta-World 3.0.0, MuJoCo 3.3.7, Gymnasium 1.1.1, a
16 GB RTX 4070 Ti Super and 32 GB RAM. The current environment inventory is in
[`environment/observed-packages.txt`](../environment/observed-packages.txt).
It records the observed development environment, not a guaranteed clean-install
lockfile. Data-only checks and figure regeneration are the self-contained path
tested for this portfolio release; a fresh simulator installation was not performed
during packaging.

Consult the retained [upstream installation instructions](../jepa-wms/README.md)
for native dependencies. The upstream `pyproject.toml` targets Python 3.10 and newer
PyTorch requirements than this study's working environment; blindly installing it
into the recorded Python 3.11 environment is not a reproduction of these runs.
Use the study's vendored source on the Python path by running modules from
`jepa-wms/`. No new model is trained by this project.

The Reach-Wall config expects `checkpoints/mw_jepa-wm.pth.tar` at the portfolio
root. Download the released Meta-World JEPA-WM checkpoint using the upstream
download link or Hugging Face repository. The observed file's SHA-256 was:

```text
c3297772c7af4e84c28bd0c0937e22398a888848305014bb3ab3f1508a310bd8
```

Reach-Wall uses the published normalization statistics and scripted expert-goal
observations; it does not require the Meta-World trajectory dataset. Wall's legacy
replay path uses the Wall dataset/preprocessing configuration. Obtain any required
dataset through the upstream instructions and its access conditions; no datasets
or model weights are redistributed here.

### Reach-Wall command sequence

From the portfolio root, using the original Windows/conda convention:

```powershell
conda activate AI
New-Item -ItemType Directory -Force runs | Out-Null
$env:JEPAWM_LOGS = (Resolve-Path '.\runs').Path
$env:USE_LIBUV = '0'
Set-Location jepa-wms

# A: learned model, full candidate capture, native actual execution
python -X utf8 -m evals.main --fname configs/evals/simu_env_planning/mw/jepa-wm/reach_wall_a.yaml --debug

# B/C: replay and rescore A's completed decision pools
python -X utf8 -m evals.simu_env_planning.planning.reach_wall_b --all
python -X utf8 -m evals.simu_env_planning.planning.reach_wall_c
python -X utf8 -m evals.simu_env_planning.planning.analyze_reach_wall_terminal

# Independent B/C controllers, each starting from A's paired initial states
python -X utf8 -m evals.simu_env_planning.planning.reach_wall_b_closed_loop --all
python -X utf8 -m evals.simu_env_planning.planning.reach_wall_c_closed_loop --all
```

`--debug` selects one process; YAML `quick_debug: false` preserves the full CEM
budget. A's `--resume` resumes at episode boundaries after validating config and
saved RNG. Independent B/C maintain their own resumable episode progress. Use the
same source run/config when resuming. Outputs go to ignored `runs/` directories.

The A config evaluates candidates in batches of 32 to control GPU memory; it still
uses the full 300-sample population and ten elites. Changing batch shapes can change
floating-point scores and near-tied elite choices. Equal seed and proposal budget
do not guarantee bitwise reproduction on another hardware/software stack.

After completing the native runs, the original scripts provide distance figures,
selected-plan audits and resumable simulator-only candidate replays:

```powershell
python -m evals.simu_env_planning.planning.plot_reach_wall_distance
python -m evals.simu_env_planning.planning.analyze_reach_wall_prefix
python -m evals.simu_env_planning.planning.replay_reach_wall_prefix_candidates --help
python -m evals.simu_env_planning.planning.replay_reach_wall_initial_search --help
```

The `--help` commands expose worker/pool selectors before expensive replay. Read
the [code map](code-map.md) and [protocol](experiments.md) for their conditional
state selection and measurement units.

### Wall command sequence

Set `JEPAWM_LOGS` to the portfolio `runs` directory, `USE_LIBUV=0` on the recorded
Windows setup, and `JEPAWM_DSET` to the parent of the required Wall dataset.
From `jepa-wms/`:

```powershell
python -X utf8 -m evals.main --fname configs/evals/simu_env_planning/wall/jepa-wm/pool650_i10.yaml --debug
python -X utf8 -m evals.simu_env_planning.planning.candidate_replay
python -m evals.simu_env_planning.planning.analyze_candidates
python -m evals.simu_env_planning.planning.analyze_wall_terminal
```

`candidate_replay.py` is a historical executable script that performs work at
module import. Run it as a module; do not import it as a helper. The original Wall
action-bounds limitation is intentionally preserved rather than silently changing
the experiment. Full reruns can be expensive; source paths and checks are designed
to detect incompatible saved inputs.
